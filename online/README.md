# MY TECH online — บัญชี สต๊อก และเงินเดือน

## รายรับ–รายจ่ายและยอดคงค้าง

หน้า **รายรับ · รายจ่าย** แสดงยอดค้างจาก Invoice ขาย ค่าเรียน บิลผู้ขาย ใบสั่งซื้อ และเงินเดือนสุทธิที่ยังไม่จ่าย เชื่อมไปยังหน้ารายละเอียดได้ทันที ส่วน **รายงาน** รวมรายการเงินและเอกสารทุกส่วนที่ผู้ใช้มีสิทธิ์ดู พร้อม CSV และรายงานสำหรับพิมพ์/PDF ที่ใช้ตัวกรองเดียวกัน

ค่าใช้จ่ายที่บันทึกแล้วรวมรายจ่าย เคลียร์เงินเบิก เงินเดือนสุทธิที่จ่าย และดอกเบี้ย เงินเดือนฉบับร่างกับบิลยังไม่จ่ายแสดงเป็นค้างจ่าย Invoice ที่ยังไม่รับเงินเป็นค้างรับ ไม่เพิ่มเงินในบัญชีและไม่ลงรายรับหรือรายจ่ายซ้ำ การคืนต้นหนี้ เงินเบิก และเจ้าของถอนเป็นเงินออกที่แสดงแยกจากค่าใช้จ่าย ส่วนต้นทุนวัสดุเบิกสุทธิหลังคืนไม่บวกซ้ำกับเงินซื้อของ ข้อมูลส่วนตัวและรายละเอียดเงินเดือนเฉพาะเจ้าของ

เมนู **บิลค่าใช้จ่าย · Invoice ผู้ขาย** บันทึกผู้ขาย เลขบิล หมวด วันที่ กำหนดชำระ ยอดเงิน โครงการ หลักฐาน และจ่ายบางส่วนได้ เชื่อมใบสั่งซื้อเดิมเมื่อเป็นรายการเดียวกัน ระบบใช้ยอดชำระเดียวกันและรวมเจ้าหนี้ครั้งเดียว บิลส่วนตัวใช้บัญชีส่วนตัวและเปลี่ยนขอบเขตบิลเดิมไม่ได้ หากกรอกผิดให้กลับรายการจ่าย ยกเลิกบิล และสร้างใหม่

ตัวกรองรายการเงินใช้วันที่รายการ เอกสารใช้วันที่ออก เงินเดือนใช้เดือนของสลิป ทะเบียนและหนี้ใช้วันที่สร้างในเวลาไทย ยอดคงค้างหักการรับ/จ่ายที่ยังมีผลทุกวันที่ จึงไม่ใช่รายงานย้อนหลัง ณ วันสิ้นงวด

หน้าลายเซ็นตรวจภาพจริงจากที่เก็บส่วนตัวและแจ้งจำนวนเอกสารที่ยังไม่มีภาพ เจ้าของเลือกใช้ลายเซ็นปัจจุบันกับเอกสารที่ยังไม่มีได้เอง โดยเก็บลายเซ็นเดิมของเอกสารอื่นไว้ รายงานพิมพ์ใช้ลายเซ็นปัจจุบัน บิลผู้ขายเป็นบันทึกอนุมัติภายในของ MY TECH มิใช่ต้นฉบับเอกสารจากผู้ขาย


## แก้ไขยอดยกมาและอนุญาตยอดติดลบ

เจ้าของไป **ตั้งค่าและสำรองข้อมูล → บัญชีเงินสดและธนาคาร → แก้ไขยอดยกมา** ใส่ยอดเริ่มต้นใหม่ วันที่ปรับ และเหตุผล ฟอร์มแสดงส่วนต่างกับยอดคงเหลือหลังบันทึกก่อนยืนยัน ระบบเก็บรายการยอดยกมาเดิมไว้ และเพิ่มรายการ opening_adjustment เฉพาะส่วนต่าง ไม่สร้างรายรับ ค่าใช้จ่าย หรือใบเสร็จเพิ่ม เปิดดูยอดเดิม/ใหม่และเหตุผลได้ใน **ประวัติยอดยกมา** ของบัญชีนั้น

ตัวเลือก **อนุญาตยอดคงเหลือติดลบสำหรับบัญชีนี้** เปิด/ปิดได้เฉพาะเจ้าของ ผ่านฟอร์มตั้งหรือแก้ยอดยกมา เมื่อเปิด สามารถตั้งยอดยกมาติดลบและจ่ายค่าใช้จ่าย/ค่าแรงเกินเงินคงเหลือได้ บัญชีอื่นยังป้องกันเงินติดลบเหมือนเดิม การปิดตัวเลือกต้องทำให้ยอดคงเหลือปัจจุบันไม่ติดลบ ส่วนเงื่อนไขหนี้ ใบสั่งซื้อ และยอด Invoice ยังคงตรวจตามเอกสาร

รายการปรับยอดเก็บประวัติถาวร หากกรอกผิดอีกให้ใช้ปุ่มแก้ยอดยกมาแทนการกลับรายการ ระบบตรวจ revision ป้องกันแก้ทับจากอีกเครื่อง สำรอง/กู้คืนเก็บทั้งยอดติดลบและประวัติครบ

AI ใช้ action entry โดยระบุ type:'opening', correctOpening:true, expectedOpeningRevision (บัญชีเก่าที่ไม่มีค่าใช้ 1), amount เป็นยอดยกมาใหม่หน่วยบาท, date และเหตุผลใน note ตั้ง allowNegative:true เมื่อเจ้าของอนุญาตติดลบ จำนวนติดลบใช้ได้เฉพาะยอดยกมา ประเภทรายรับ/รายจ่ายยังใช้จำนวนบวกตามประเภท อ่านบัญชีและรายการล่าสุดก่อนแก้เสมอ

## จ่ายเงินเดือนและค่าแรงรายวัน / รายชั่วโมง

หน้า **เงินเดือนพนักงาน** มีส่วน **จ่ายเงินค่าแรง · ปรับแก้ก่อนจ่าย** อยู่ด้านบน เลือกพนักงานและงวดที่ยังไม่จ่าย แล้วปรับเงินเดือนเหมาจ่าย จำนวนวัน/ชั่วโมง อัตราค่าแรง รายได้เพิ่ม รายการหัก และหมายเหตุได้ก่อนยืนยัน ระบบคิดจำนวน × อัตราด้วยจำนวนเต็มและปัดเป็นสตางค์ครั้งเดียว จำนวนใช้ทศนิยมได้ 3 ตำแหน่ง เช่น 7.5 ชั่วโมง

ค่าแรงตามจำนวนบวกกับฐานเงินเดือนและรายได้เพิ่ม หากใช้แทนยอดเดิมให้ตั้งฐานเป็น 0 และลบรายการเดิมที่ใช้แทนออกก่อน ไม่แปลงข้อมูลเก่าหรือปรับยอดจริงอัตโนมัติ ยังคงหนึ่งสลิปต่อพนักงานต่อเดือน

เมื่อมีการปรับก่อนจ่าย ต้องระบุเหตุผล ระบบบันทึกข้อมูลก่อนแก้ไว้ในประวัติส่วนตัว ปรับสลิปและสร้างรายจ่ายสุทธิเพียงหนึ่งรายการในการบันทึกเดียว หากเงินไม่พอหรือข้อมูลเปลี่ยนจากอีกเครื่อง ยอดเดิมยังคงอยู่ ป้องกันการจ่ายซ้ำด้วย requestId ยอดจ่ายเข้าในรายรับ–รายจ่ายและรายงาน สลิป/CSV แสดงค่าแรงแยกจากรายได้เพิ่มอื่น ลายเซ็นของงวดเดิมยังคงเดิม

การยืนยันจ่ายเป็นการบันทึกบัญชี ไม่ใช่คำสั่งโอนธนาคาร งวดที่จ่ายแล้วต้องกลับรายการจ่ายเดิมก่อนแก้ยอด เงินเดือน ค่าแรง สลิป และหลักฐานทั้งหมดเฉพาะเจ้าของและไม่ส่ง Trello แม้ระบุปลายทาง

AI ใช้ payrollSave.wage={unit:'day'|'hour',quantity:'2.5',rate:'500.25'} หรือ enabled:false เพื่อปิดการคิดตามจำนวน การแก้และจ่ายพร้อมกันใช้ payrollPay.expectedRevision และ adjustment ซึ่งประกอบด้วย baseSalary, wage, earnings, deductions, note, editReason อ่านงวดล่าสุดก่อนส่งเสมอ

## แก้ไข Invoice และใบเสนอราคา

ไปที่ **ใบเสนอราคา · Invoice → แก้ไข** หรือกด **แก้ไข Invoice** จากหน้าเอกสารพิมพ์ ฟอร์มโหลดข้อมูลเดิมและให้ระบุเหตุผลก่อนบันทึก คง ID เลขที่เอกสาร และลายเซ็นเดิมไว้ พร้อมเก็บข้อมูลก่อนแก้ในประวัติเฉพาะเจ้าของ ยอดคงค้างและรายงานปรับจากเอกสารเดิม ไม่สร้าง Invoice หรือรายรับเพิ่ม

แก้ชื่อ ที่อยู่ โทรศัพท์ และเลขผู้เสียภาษีในเอกสารได้ โดยไม่แก้ทะเบียนลูกค้าหรือใบเสร็จเดิม Invoice ที่รับชำระแล้วแก้ยอดใหม่ได้ไม่น้อยกว่าเงินที่รับแล้ว และเปลี่ยนรหัสผู้ชำระ/การลงทะเบียนไม่ได้จนกว่าจะกลับรายการรับเงิน ใบเสนอราคาที่ออก Invoice ต่อแล้วแก้ได้เฉพาะกำหนดและหมายเหตุ เอกสารยกเลิกแก้ไม่ได้

AI ใช้ action เดิม **document** โดยเพิ่ม id, expectedRevision (เอกสารเก่าไม่มีค่าให้ใช้ 1) และ editReason อ่านเอกสารก่อนแก้ทุกครั้ง ถ้าข้อมูลเปลี่ยนระหว่างเปิดฟอร์ม ระบบปฏิเสธและให้โหลดใหม่ ป้องกันแก้ทับจากอีกเครื่อง การแก้ไขใช้เส้นทาง Trello เดิมเมื่อเลือกใช้การส่งตามค่าเดิม

## ลายเซ็นเอกสาร

เจ้าของไป ตั้งค่าและสำรองข้อมูล → เพิ่ม / แก้ไขลายเซ็น ใส่ชื่อ ตำแหน่ง วาดด้วยเมาส์/นิ้ว หรืออัปโหลด PNG/JPG/WebP รูปเก็บส่วนตัวใน R2 ขนาดหลังแปลงไม่เกิน 512 KB เอกสารใหม่เก็บสำเนาชื่อ ตำแหน่ง และรหัสภาพของตัวเอง การเปลี่ยนลายเซ็นไม่เปลี่ยนเอกสารเก่าที่ออกแล้ว ใบเสนอราคา Invoice และใบเสร็จแสดงลายเซ็นในการพิมพ์และไฟล์ที่เลือกส่ง Trello ส่วนสลิปเงินเดือนแสดงลายเซ็นเฉพาะในโปรแกรมและการพิมพ์

ผู้เข้าชมทั่วไปไม่ได้รับภาพหรือข้อมูลลายเซ็นใน state/เอกสารสาธารณะ ไฟล์สำรองส่วนตัวของเจ้าของมี signatureFiles รวมรูปที่เอกสารเก่าและใหม่อ้างอิง กู้คืนจะสร้างรหัสไฟล์ใหม่พร้อมแก้การอ้างอิงให้ครบ รูปไม่ถูกเก็บใน GitHub หรือ localStorage

## ส่ง Trello อัตโนมัติ

เจ้าของเปิดเมนู Trello → ตั้ง API Key / Token ในหน้าเว็บ → อ่านบอร์ดและหัวข้อ → เลือกบอร์ดหลัก → ตั้งค่าส่งอัตโนมัติ ผู้แก้ไขใช้ได้เฉพาะบอร์ดหลักที่เจ้าของกำหนด ห้ามส่ง Token ในแชตหรือเก็บใน GitHub

ฟอร์มรับ–จ่าย ใบเสนอราคา Invoice และฟอร์มรายการอื่นมีตัวเลือกไม่ส่ง ใช้ค่าอัตโนมัติ สร้างหัวข้อใหม่ หรือเพิ่มข้อความในการ์ดเดิม พร้อมเลือกลิสต์ หัวข้อไฟล์ และหลายไฟล์ (PNG/JPG/WebP/PDF/DOCX/XLSX/CSV/TXT ไฟล์ละไม่เกิน 10 MB) ไฟล์ถูกอัปโหลดตรงไป Trello ไม่เปิดไฟล์หลักฐานให้บุคคลทั่วไปเข้าถึงใน MY TECH

บันทึกรายรับแล้วออกใบเสร็จ RC จากรายการรับเงินจริง ไม่เพิ่มยอดเงินซ้ำ เมื่อกลับรายการจะปรับสถานะใบเสร็จและแจ้งเอกสารที่เชื่อมไว้ ข้อความรายการส่งเป็นความเห็นบนการ์ด ส่วนเอกสารส่งเป็น **HTML ภาษาไทยแบบสมบูรณ์** เปิดและพิมพ์เป็น PDF ได้ ไม่ใช่การสร้าง PDF ในเซิร์ฟเวอร์อัตโนมัติ

ระบบใช้ outbox ถาวรใน D1 และล็อกการส่ง รายการบัญชี/หลักฐานกับงานส่งบันทึกพร้อมกันด้วย revision guard หากปลายทางขัดข้องเงินไม่ถูกลงซ้ำ มีสถานะรอส่ง กำลังส่ง สำเร็จ ผิดพลาด และผลไม่แน่นอน กรณีผลไม่แน่นอนจะตรวจรหัสอ้างอิง ข้อความ และชื่อไฟล์ก่อนส่งซ้ำ การยืนยันส่งใหม่หลังตรวจด้วยตนเองมีในหน้าสถานะ

ส่งเบื้องหลังแบบมีขอบเขตหลังบันทึก และขณะเปิดโปรแกรมมีการตรวจสถานะเป็นระยะ งานค้างคงอยู่หากปิดหน้าและจะส่งต่อเมื่อเปิด/ทำรายการอีกครั้ง ไม่มี cron ที่รับประกัน retry ขณะปิดโปรแกรม ข้อมูลส่วนตัวทั่วไปไม่ใช้ค่าอัตโนมัติของกิจการ ต้องให้เจ้าของเลือกส่งเป็นรายรายการ เงินเดือน สลิป และหลักฐานเงินเดือนห้ามส่ง Trello กู้คืนข้อมูลต้องรอจนไม่มีงานกำลังส่งและจะยกเลิกงานค้างของข้อมูลชุดเก่า

รุ่นออนไลน์ต่อยอดจาก krarokkrara-alt/-Mytech โดยคง model การเงิน สต๊อก เอกสาร และข้อมูลส่งต่อเดิม ใช้ Cloudflare Worker + D1 ถาวร และ R2 สำหรับหลักฐาน/สำเนาก่อนกู้คืน ผ่าน Sites และเข้าสู่ระบบด้วย ChatGPT

## สิทธิ์

- ผู้เข้าชม: ดูข้อมูลกิจการ ข้อมูลติดต่อและรายละเอียดชำระเงินถูกซ่อน ไม่มีสิทธิ์เขียน API
- ผู้แก้ไข: เจ้าของเพิ่มด้วยอีเมลในหน้าจัดการสิทธิ์ บันทึกกิจการและสต๊อกได้ ถอนสิทธิ์มีผลกับคำขอถัดไป
- เจ้าของ: กำหนด `OWNER_EMAIL` เป็น secret ฝั่งโฮสต์ ไม่มีการตั้งเจ้าของโดยผู้มาเยือนคนแรก จัดการเงินส่วนตัว เงินเดือน ผู้แก้ไข สำรองและกู้คืน

Identity headers มาจาก Sites dispatch เท่านั้น ห้ามนำ Worker ไปเสิร์ฟตรงบนโฮสต์ที่ยอมให้ผู้เข้าชมปลอม `oai-authenticated-user-*` ได้ ไม่ใช้ localStorage เก็บบัญชี

## เงินเดือน

เพิ่มทะเบียนพนักงาน เงินเดือนพื้นฐาน บัญชีรับเงิน ตำแหน่งและสถานะ สร้างเงินเดือนรายเดือนโดยเพิ่มชื่อรายได้และรายการหักเองได้ เช่น OT โบนัส เบี้ยเลี้ยง ภาษี ประกันสังคม เงินเบิกล่วงหน้า มีเครื่องคิดจำนวน × อัตรา ไม่มีสูตรกฎหมายภาษีหรือประกันสังคมอัตโนมัติ

ฉบับร่างไม่ลงบัญชี กดบันทึกว่าจ่ายแล้วจึงลงค่าใช้จ่ายสุทธิครั้งเดียวและหักบัญชีกิจการ ไม่สั่งโอนธนาคาร จ่ายแล้วแก้ไขไม่ได้ หากบันทึกผิดให้กลับรายการเงินก่อน จากนั้นแก้ไขหรือยกเลิกเงินเดือน เงินเดือนแต่ละงวดเก็บสำเนารายละเอียดพนักงาน ณ วันจัดทำ มีสลิปพิมพ์ PDF/ภาพและส่งออก CSV

## การตั้งค่าโฮสต์

`.openai/hosting.json` เก็บเฉพาะ Site ID และชื่อ binding ฐานข้อมูล ค่า `OWNER_EMAIL` และ `DATA_KEY` (กุญแจ AES 32 bytes แบบ base64) ต้องตั้งผ่าน runtime environment secrets ไม่ commit รหัสลับ Trello ตั้งค่าโดยเจ้าของผ่านหน้าเว็บแล้วเข้ารหัสเก็บฝั่งเซิร์ฟเวอร์ ไม่รวมใน backup

ข้อมูลส่งต่อเริ่มต้นมี pending 9 รายการ เงิน ลูกค้า สินค้าและเอกสารว่าง ไม่ยืนยันยอดเดิมจากแชตอัตโนมัติ สำรอง JSON แบบ streaming รวมเงินเดือนและหลักฐาน โดยไม่รวมสิทธิ์ผู้แก้ไขหรือรหัสลับ กู้คืนจะบันทึกสำเนาก่อนแทนที่และเจ้าของดาวน์โหลดสำเนาได้ในหน้าตั้งค่า หน้ากู้คืนรองรับไฟล์ JSON ไม่เกิน 100 MB หลักฐานแต่ละไฟล์ไม่เกิน 10 MB ส่งหลักฐานแยกทีละไฟล์ก่อน commit ครั้งเดียว มี revision ป้องกันการทับการเปลี่ยนแปลงระหว่างส่งไฟล์

ป้องกันการส่งรายการซ้ำด้วย requestId และป้องกันข้อมูลทับกันจากหลายเครื่องด้วย revision หากเกิด conflict ระบบให้โหลดใหม่และตรวจรายการก่อนส่งซ้ำ การเชื่อมเขียน Trello จริงต้องทดสอบด้วยสิทธิ์และรายการที่เจ้าของอนุญาต
# บันทึกผ่าน AI / Codex

แนบรูปหรือไฟล์จากแชตใน `mytech_save.files` เพื่อบันทึกหลักฐานพร้อมรายการ หรือใช้ `mytech_attach_files` สำหรับรายการเดิม เครื่องมือประกาศ `openai/fileParams` ตามสัญญาไฟล์ของแพลตฟอร์ม (`download_url`, `file_id`, `mime_type`, `file_name`) รองรับไม่เกิน 10 ไฟล์ ไฟล์ละ 10 MB และไม่เก็บลิงก์ดาวน์โหลดชั่วคราวลงฐานข้อมูล หากบางไฟล์ไม่สำเร็จ ผลลัพธ์จะบอกว่ารายการบันทึกแล้วและไฟล์ใดค้าง ให้ส่งคำขอเดิมซ้ำโดยใช้ requestId และ file_id เดิม ลิงก์ชั่วคราวที่หมดอายุเปลี่ยนใหม่ได้

**เงินเดือน สลิป พนักงาน และหลักฐานเงินเดือนเก็บเฉพาะในโปรแกรม ห้ามส่ง Trello แม้เจ้าของระบุปลายทาง** หลักฐานเงินเดือนที่แนบกับรายการทั่วไปต้องระบุ `payrollOnly: true` ระบบเก็บเครื่องหมายนี้ถาวร จำกัดการอ่านเฉพาะเจ้าของ และรักษาเครื่องหมายผ่านการสำรอง/กู้คืน ตัวส่งตรวจนโยบายซ้ำและยกเลิกงานที่ค้างก่อนเรียก Trello การเปลี่ยนนี้ไม่ลบรายการที่เคยส่งไป Trello สำเร็จก่อนหน้า

ลายเซ็นอยู่ที่ `/?page=signature` เจ้าของเขียนด้วยเมาส์/นิ้ว/ปากกา โหลดลายเซ็นเดิมมาแก้ ใช้ยางลบ ย้อนกลับ ล้าง และอัปโหลดรูปได้ เอกสารที่ออกไปแล้วเก็บสำเนาลายเซ็นเดิม

เว็บมี Site MCP endpoint `POST /mcp` และประกาศ `capabilities: ["mcp"]` ใน hosting manifest แล้ว เมื่อเผยแพร่โดยเจ้าของ Sites จะจัดเตรียมปลั๊กอินส่วนตัวให้เชื่อมกับ ChatGPT/Codex ผ่านหน้าติดตั้งปลั๊กอิน ไม่ต้องส่ง API Key ของ Trello หรือรหัสฐานข้อมูลให้ AI

- `mytech_status`: ตรวจบัญชี สิทธิ์ วันที่กรุงเทพ และคำสั่งที่ใช้ได้
- `mytech_list`: ค้นรายการเดิมเพื่อเลือกรหัสบัญชี/ลูกค้า/พนักงาน/สินค้าให้ถูกต้อง
- `mytech_action_schema`: ดูช่องที่จำเป็นของแต่ละประเภทก่อนบันทึก
- `mytech_save`: บันทึกด้วย model, CAS, ประวัติ และ Trello outbox ชุดเดียวกับหน้าเว็บ
- `mytech_attach_files`: แนบภาพและหลักฐานจากแชตเข้ารายการที่มีอยู่แล้ว โดยไม่สร้างรายการบัญชีใหม่

กรอกจำนวนเงินเป็นข้อความหน่วย **บาท** เช่น `1500.50`; ข้อมูลที่อ่านกลับใช้จำนวนเต็มหน่วย **สตางค์** จำนวนสินค้าใช้ข้อความหน่วยจริงขาเข้า และจำนวนเต็มหนึ่งในพันขาออก วันที่ระบุเป็น `YYYY-MM-DD` ตาม Asia/Bangkok

แต่ละรายการใช้ `requestId` ใหม่และคงค่าเดิมเมื่อส่งซ้ำหลัง timeout ระบบผูกคำขอกับตัวตนผู้เรียกและ fingerprint ของข้อมูล ป้องกันบันทึกซ้ำและปฏิเสธการนำรหัสเดิมไปใช้กับเจตนาอื่น ต้องตรวจ `success`, `result` และ `duplicate` ก่อนบอกผู้ใช้ว่าบันทึกสำเร็จ

สิทธิ์มาจากตัวตนที่ Sites ยืนยันและสมาชิกในฐานข้อมูลทุกครั้ง เจ้าของจัดการเงินเดือน/ข้อมูลส่วนตัวได้ ผู้แก้ไขบันทึกเฉพาะส่วนที่มีสิทธิ์ ผู้เข้าชมใช้คำสั่งเขียนไม่ได้ ตัวเชื่อมนี้ไม่ให้แก้สิทธิ์ อ่านรหัสเชื่อมต่อ กู้คืนฐานข้อมูล หรือใส่ลายเซ็นแทนผู้ใช้

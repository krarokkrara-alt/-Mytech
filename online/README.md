# MY TECH online — บัญชี สต๊อก และเงินเดือน

รุ่นออนไลน์ต่อยอดจาก krarokkrara-alt/-Mytech โดยคง model การเงิน สต๊อก เอกสาร และข้อมูลส่งต่อเดิม ใช้ Cloudflare Worker + D1 ถาวร และ R2 สำหรับหลักฐาน/สำเนาก่อนกู้คืน ผ่าน Sites และเข้าสู่ระบบด้วย ChatGPT

## สิทธิ์

- ผู้เข้าชม: ดูข้อมูลกิจการ ข้อมูลติดต่อและรายละเอียดชำระเงินถูกซ่อน ไม่มีสิทธิ์เขียน API
- ผู้แก้ไข: เจ้าของเพิ่มด้วยอีเมลในหน้าจัดการสิทธิ์ บันทึกกิจการและสต๊อกได้ ถอนสิทธิ์มีผลกับคำขอถัดไป
- เจ้าของ: กำหนด `OWNER_EMAIL` เป็น secret ฝั่งโฮสต์ ไม่มีการตั้งเจ้าของโดยผู้มาเยือนคนแรก จัดการเงินส่วนตัว เงินเดือน ผู้แก้ไข สำรองและกู้คืน

Identity headers มาจาก Sites dispatch เท่านั้น ห้ามนำ Worker ไปเสิร์ฟตรงบนโฮสต์ที่ยอมให้ผู้เข้าชมปลอม `oai-authenticated-user-*` ได้ ไม่ใช้ localStorage เก็บบัญชี

## เงินเดือน

เพิ่มทะเบียนพนักงาน เงินเดือนพื้นฐาน บัญชีรับเงิน ตำแหน่งและสถานะ สร้างเงินเดือนรายเดือนโดยเพิ่มชื่อรายได้และรายการหักเองได้ เช่น OT โบนัส เบี้ยเลี้ยง ภาษี ประกันสังคม เงินเบิกล่วงหน้า มีเครื่องคิดจำนวน × อัตรา ไม่มีสูตรกฎหมายภาษีหรือประกันสังคมอัตโนมัติ

ฉบับร่างไม่ลงบัญชี กดบันทึกว่าจ่ายแล้วจึงลงค่าใช้จ่ายสุทธิครั้งเดียวและหักบัญชีกิจการ ไม่สั่งโอนธนาคาร จ่ายแล้วแก้ไขไม่ได้ หากบันทึกผิดให้กลับรายการเงินก่อน จากนั้นแก้ไขหรือยกเลิกเงินเดือน เงินเดือนแต่ละงวดเก็บสำเนารายละเอียดพนักงาน ณ วันจัดทำ มีสลิปพิมพ์ PDF/ภาพและส่งออก CSV

## พัฒนาและทดสอบ

ใช้ Node.js >=24.11.1 ไม่มี npm dependencies

```
node scripts/build.mjs
node --test tests/*.test.mjs my-tech-accounting/tests/model.test.mjs
node scripts/preview.mjs
```

Preview ที่ 127.0.0.1:4318 ใช้ฐานข้อมูลชั่วคราวและตัวตนทดสอบเท่านั้น ไม่ใช่ฐานข้อมูลจริง ลิงก์ /preview-role/owner มีเฉพาะเซิร์ฟเวอร์ preview ไม่อยู่ใน Worker production

ไฟล์ `my-tech-accounting/server.mjs` ยังคงเป็นรุ่น local เดิม ไม่ใช่ entrypoint ออนไลน์ การเผยแพร่ใช้ `dist/server/index.js` สร้างจาก scripts/build.mjs และ migration ใน drizzle/

## การตั้งค่าโฮสต์

`.openai/hosting.json` เก็บเฉพาะ Site ID และชื่อ binding ฐานข้อมูล ค่า `OWNER_EMAIL` และ `DATA_KEY` (กุญแจ AES 32 bytes แบบ base64) ต้องตั้งผ่าน runtime environment secrets ไม่ commit รหัสลับ Trello ตั้งค่าโดยเจ้าของผ่านหน้าเว็บแล้วเข้ารหัสเก็บฝั่งเซิร์ฟเวอร์ ไม่รวมใน backup

ข้อมูลส่งต่อเริ่มต้นมี pending 9 รายการ เงิน ลูกค้า สินค้าและเอกสารว่าง ไม่ยืนยันยอดเดิมจากแชตอัตโนมัติ สำรอง JSON แบบ streaming รวมเงินเดือนและหลักฐาน โดยไม่รวมสิทธิ์ผู้แก้ไขหรือรหัสลับ กู้คืนจะบันทึกสำเนาก่อนแทนที่และเจ้าของดาวน์โหลดสำเนาได้ในหน้าตั้งค่า หน้ากู้คืนรองรับไฟล์ JSON ไม่เกิน 100 MB หลักฐานแต่ละไฟล์ไม่เกิน 10 MB ส่งหลักฐานแยกทีละไฟล์ก่อน commit ครั้งเดียว มี revision ป้องกันการทับการเปลี่ยนแปลงระหว่างส่งไฟล์

ป้องกันการส่งรายการซ้ำด้วย requestId และป้องกันข้อมูลทับกันจากหลายเครื่องด้วย revision หากเกิด conflict ระบบให้โหลดใหม่และตรวจรายการก่อนส่งซ้ำ การเชื่อมเขียน Trello จริงต้องทดสอบด้วยสิทธิ์และรายการที่เจ้าของอนุญาต
